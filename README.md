**一句话**：把安卓手机里那些「丢了就再也找不回来」的分区，一键备份到电脑。

**全设备通用** —— 不绑定任何机型，任何已 root 的安卓手机都能用。平台（高通 / 联发科 / 三星 / 展锐 / Tensor）与分区价值由程序**按语义自动推断**，不需要为每台机器写配置。

## 一、快速开始

### 环境要求

- **Python 3.8+**（含 tkinter，官方安装包默认自带）
- **ADB** —— 从 [platform-tools](https://developer.android.com/tools/releases/platform-tools) 下载，
  放到 `adb/adb.exe`（Windows）或 `adb/adb`（Linux/macOS），或直接加进系统 PATH
- 一台**已 root** 的安卓手机（Magisk / KernelSU / APatch 均可）

> 本仓库不含 ADB 二进制（8 MB 的二进制进 git 历史后无法瘦身），请自行下载。

### 运行

```bash
git clone <本仓库地址>
cd 安卓分区备份工具          # 或你 clone 下来的目录名

# 把 platform-tools 里的 adb 放进来（三选一）
#   A. 复制到 adb/adb.exe
#   B. 加进系统 PATH
#   C. 什么都不做 —— 程序会自动从 PATH 找

python backup_gui.py         # 启动图形界面
```

Linux / macOS 用户可直接用附带的启动脚本（会自动挑一个带 tkinter 的 Python）：

```bash
./run.sh
```

命令行版（无界面，适合脚本化）：

```bash
python backup_core.py --adb <adb路径> --preset critical --out <输出目录>
python backup_core.py --adb <adb路径> --list        # 只列出设备分区与分级
```

### 手机侧准备

1. 设置 → 关于手机 → 连点「版本号」7 次开启开发者选项
2. 开发者选项 → 打开 **USB 调试**
3. 用数据线连电脑，手机上弹出「允许 USB 调试」→ **勾选「一律允许」并确定**
4. **解锁手机屏幕**（锁屏状态下 adb 常被系统拦截）
5. 确保手机已 root，并在 root 管理器里给 **Shell** 授权

程序会自动识别设备状态，并在界面上提示当前卡在哪一步。

## 二、备份什么 —— 四级分类

程序不看机型，而是**按分区名的语义**自动分级：

| 级别 | 含义 | 典型分区 | 丢了会怎样 |
|---|---|---|---|
| **★ Tier 1 不可再生** | 含设备唯一数据 | `persist` `modemst1/2` `fsg` `nvdata` `efs` `devinfo` `frp` `secdata` | **永久损坏，官方固件也救不回** |
| **Tier 2 root 基准** | 你修补过的系统分区 | `init_boot_a/b` `boot_a/b` `vbmeta*` `dtbo*` | 官方只有未修补版，root 状态丢失 |
| **Tier 3 固件可重建** | 官方刷机包里就有 | `system` `vendor` `abl` `modem` `super` | 重刷官方包即可 |
| **Tier 4 低价值** | 厂商备份槽/日志/对齐 | `bk*` `ALIGN*` `logfs` `oops` `rawdump` | 无意义 |

**预设方案**（界面上一键切换）：

| 预设 | 内容 | 典型体积 |
|---|---|---|
| **关键分区（推荐）** | 只含 Tier 1 | ~80 MB |
| **关键 + root 基准** | Tier 1 + Tier 2（默认）| ~1 GB |
| 全部有价值分区 | Tier 1+2+3 | 数 GB ~ 数十 GB |
| 全部分区 | 所有 | 可达 200 GB+ |

> 📚 **分级规则经过外部核实**：本文的分区名单与 [onfix.cn《手机字库基带使用命令备份指南》](https://onfix.cn/course/4780?bid=1&mid=28642)
> 独立列出的名单逐条一致（高通 `fsg/fsc/modemst1/modemst2`；联发科 `nvram/nvdata/nvcfg/persist/protect1/protect2/seccfg`）。
> 该来源同时印证了「联发科的 by-name 路径与高通不同，需要多路径探测」这一点。

> ⚠️ `userdata`（个人数据，可达数百 GB）、`super`（动态分区容器）、`metadata`（加密元数据）
> **永远不会被预设自动勾选**，需要你手动选中 —— 避免"全选"顺手带上几百 GB。

## 三、备份文件放哪儿

```
安卓分区备份工具_便携版\
└── Backups\                        ← 程序目录下自动创建
    ├── 我的备份\                    ← 你自定义的名称
    │   ├── .device_info            ← 设备指纹（用于判断"同一台设备"）
    │   ├── README.md               ← 自动生成：设备信息 + 差异对比 + 文件清单
    │   ├── manifest.txt            ← 逐项 SHA256
    │   ├── backup_log.txt          ← 本次完整日志
    │   ├── img\                    ← 分区镜像
    │   └── gpt\                    ← GPT 分区表（头/尾/sgdisk格式/布局文本）
    └── 我的备份_20260918\           ← 同名再次备份 → 自动加日期
```

### 命名与冲突规则

名称由你在界面上**自定义**（留空则用默认名 `Backup`）。同名时按以下顺序消解，**绝不覆盖任何已有备份**：

| 情况 | 结果 |
|---|---|
| 该名称尚未使用 | `我的备份` |
| 已存在，且是**同一台设备** | `我的备份_20260918` ← 追加日期 |
| 已存在，但是**别的设备** | `我的备份_20260918` ← 同样加日期，不把两台机器混一起 |
| 同一天又备了一次 | `我的备份_20260918_153000` ← 再加时分秒 |
| 还是冲突 | `我的备份_20260918_153000_2` ← 再加序号 |

**界面会实时预览最终路径**，并在备份前告诉你为什么是这个名字。

> 🛡️ 自定义名称会经过安全净化（`..\..\Windows` → `____Windows`），
> 确保备份永远落在你指定的根目录之内。

## 四、🛡️ 安全声明

**本工具只做只读导出。**

| 项目 | 说明 |
|---|---|
| 读 / 写 | 对设备分区**只有** `dd if=<分区>` 读取，**全代码不存在任何写设备分区的路径** |
| 设备端写入 | 唯一的写入是 `/sdcard/.apb_tmp` 与 `/data/local/tmp` 下的临时文件，**用完立即删除** |
| 覆盖已有备份 | **不可能** —— 创建目录用 `exist_ok=False`，重名自动改名 |
| 命令注入 | 分区名经过白名单正则 `^[A-Za-z0-9_.\-]{1,64}$` 校验 |
| 路径穿越 | 自定义名称过滤 `/ \ ..` 与 Windows 非法字符 |
| 卡死保护 | 传输停滞 120 秒自动中止（防止 adb 挂住导致无限等待）|
| 取消 | 随时可取消，已完成的分区文件保留 |

**恢复功能不提供** —— 写分区是变砖的唯一途径，请用手工流程配合 `README.md` 里的说明。

## 五、校验机制

每备份一个分区，程序都会：

1. **传输**：`adb exec-out` 把 `dd` 的输出**直接重定向**到本地文件
2. **字节数核对**：收到的字节数必须与 `blockdev --getsize64` 报的分区大小**完全一致**
3. **本地 SHA256**：对落盘文件流式计算哈希
4. **GPT 结构验证**（GPT 项）：纯 Python 解析 MBR `55AA` + GPT `EFI PART` 签名，
   并做 head ↔ tail 交叉验证（两者必须互相指向）
5. **可选设备端二次校验**：勾选后额外让设备自己算一遍 `sha256sum`，与本地比对

> 一旦字节数不符，会自动**回退**到「设备端暂存 + adb pull」这条更慢但更稳的路径重试。

### 为什么必须用 `exec-out` 而不是 `shell`？

`adb shell` 会分配 PTY，把二进制流里的 `\n` 转换成 `\r\n`，**静默损坏数据**。

实测数据（32 MB 的 persist 分区）：

| 方式 | 收到字节数 | SHA256 |
|---|---|---|
| `exec-out` | 33554432 | ✅ 与设备完全一致 |
| `shell (PTY)` | **33631171**（多 76739 字节）| ❌ 完全不匹配 |


**四条进度条 / ETA 设计要点**：

| 特性 | 说明 |
|---|---|
| **两条进度条** | 上=当前分区，下=总体（含所有已选分区 + GPT + 环境包）|
| **双 ETA** | 当前分区剩余时间 + 整体剩余时间 |
| **速度平滑** | 用指数滑动平均，不是瞬时值 —— 否则数字会乱跳 |
| **窗口标题同步** | 标题栏显示 `备份中 36%`，最小化后看任务栏也能知道进度 |
| **分阶段切换** | 传输时是百分比进度条；SHA256 校验、GPT 读取、tar 打包时自动切成来回滚动条 |
| **日志分级着色** | 紫=阶段标题，绿=成功，红=失败，黄=告警，灰=细节 |

> ⚠️ 着色判定**前缀标记优先于关键词**。像 `[!] 流式失败，回退到设备端暂存模式`
> 这种带"失败"字样的告警（回退后其实成功了），若先做关键词匹配就会被误染成红色。

### 命令行版

```sh
python backup_core.py --adb <adb路径> --preset critical --out <输出目录>
```

终端里是单行刷新进度条（`\r` 覆盖，不刷屏）：

```
  persist              [████████████░░░░░░░░░░░░░░]  48.2%   15.4 MB/32.0 MB   11.9 MB/s  剩 2s
```

## 七、常见问题

### 「未检测到设备」

界面上会显示具体卡在哪一步：

| 界面提示 | 含义 | 怎么办 |
|---|---|---|
| 未检测到设备 | adb 看不到任何设备 | 换数据线（要能传数据的）/ 装 USB 驱动 |
| **未授权** | 手机上没点"允许" | 看手机屏幕，点「允许 USB 调试」；不行就重新插拔 |
| **离线 (offline)** | 连接不稳定 | 重新插拔，或重启手机 |
| root 不可用 | `su` 被拒绝 | 在 Magisk/KernelSU/APatch 里给 Shell 授权 |

### 中文显示成方块

极少见。若出现，说明系统缺少中文字体，装一个「微软雅黑」即可。

### 备份很慢

实测约 **12-15 MB/s**（受 USB 与 adb 限制）。参考耗时：

| 内容 | 体积 | 耗时 |
|---|---|---|
| 关键分区（Tier 1）| ~80 MB | 约 10 秒 |
| 关键 + root 基准 | ~1 GB | 约 1.5 分钟 |
| `super` | 9 GB | 约 12 分钟 |
| `userdata` | 226 GB | 约 4.5 小时 |

### 想换备份位置

界面上「备份根目录」可以改。默认是程序目录下的 `Backups\`；
若程序装在 Program Files 等只读位置，会自动退回家目录的「文档」文件夹。

## 八、恢复时的四条铁律

> 1. **单机绑定**：`persist` / `modemst*` / `efs` / `nvdata` 等含设备唯一数据，
>    **严禁跨设备恢复** —— 会导致指纹失效、信号异常甚至双机 IMEI 冲突
> 2. **`secdata` 永远不要恢复旧值** —— 它是单向防回滚计数器，写旧值可能触发熔断变砖
> 3. **逻辑扇区不一定是 512** —— 高通 UFS 通常是 4096。
>    本机是多少看 `gpt\<盘>_layout.txt` 第一行，手工 `dd` 时按它算偏移
> 4. **恢复 GPT 前先留底** —— 哪怕当前 GPT 是坏的，也先 `sgdisk --backup` 存一份

### 恢复 root（最常见）

```sh
fastboot flash init_boot img\init_boot_a.img
```

### 系统内恢复不可再生分区

```sh
dd if=img\persist.img  of=/dev/block/by-name/persist  bs=1M
dd if=img\fsg.img      of=/dev/block/by-name/fsg      bs=1M
dd if=img\modemst1.img of=/dev/block/by-name/modemst1 bs=1M
sync && reboot
```

### 恢复 GPT

```sh
sgdisk --load-backup=gpt\sda_gpt_sgdisk.bin /dev/block/sda
sgdisk --move-second-header /dev/block/sda
blockdev --rereadpt /dev/block/sda
```

每个备份目录的 `README.md` 里都会带上这些命令与本机的实际分区名。

## 九、技术架构（给未来的维护者）

```
backup_gui.py          图形界面（Tkinter），只负责显示与交互
  ├─ 设备轮询线程       每 1.5 秒查一次 adb devices
  ├─ 消息队列 queue     工作线程 → 主线程的唯一通道
  └─ root.after 消息泵  主线程每 80ms 取一次队列并刷新界面

backup_core.py         核心引擎（无 GUI 依赖，可 CLI 独立运行）
  ├─ Adb                adb.exe 封装 + 能力探测
  ├─ BackupEngine       备份流程编排
  ├─ GPT 解析器         纯 Python 解析 GPT，不依赖设备端的 sgdisk
  └─ 目录命名/冲突消解   sanitize_folder_name / resolve_backup_dir

partition_profiles.py  平台特征 + 分区四级分类规则（纯数据）
```

### 三条不可违背的设计约束

1. **绝不从工作线程碰 tkinter**
   所有 `BooleanVar.get()` 之类的调用必须在主线程完成后再传给工作线程 ——
   否则会随机死锁或崩溃。这是 Tkinter 最经典的坑。

2. **必须剥离 A/B 槽位后缀再匹配规则**
   规则表按无槽位名写（`abl`），设备上实际叫 `abl_a`。
   不剥后缀会导致大量分区"未分类"。见 `classify()`。

3. **GPT 偏移必须在 Python 里算**
   shell 的 `[ ]` 比较对 253 GB 这种数值会 **32 位溢出**成负数，
   导致尾部 GPT 被静默跳过。Python 原生 64 位，没有这个问题。

### 如何支持新平台

在 `partition_profiles.py` 的 `PLATFORMS` 里加一条平台特征，
再往 `TIER1_RULES` 等规则表里补 `(fnmatch 模式, 说明)` 即可，**无需改动任何其他代码**。
